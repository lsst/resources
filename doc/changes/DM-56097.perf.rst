``ResourcePath.mremove()``, ``ResourcePath.mexists()`` and ``ResourcePath.mtransfer()`` now send a batch of URIs to each worker rather than submitting one task per URI.
The number of workers is now bounded per scheme rather than globally, so a scheme that holds no connection pool can raise the bound, and ``ResourcePath.mtransfer()`` now uses the bound for the target scheme instead of the global default.
A batch of URIs too small to be worth spreading over workers is now handled in the calling thread, since handing a couple of local file checks to a thread costs more than doing them.
The size below which this applies is set per scheme, because a scheme whose every operation is a network round trip benefits from overlapping even two URIs.
