``ResourcePath.mremove()`` and ``ResourcePath.mexists()`` now send a batch of URIs to each worker rather than submitting one task per URI.
The upper bound on the number of workers is now set per scheme, so a scheme that holds no connection pool can raise it.
A batch of URIs too small to be worth spreading over workers is now checked or removed in the calling thread, since handing a couple of local file checks to a thread costs more than doing them.
The size below which this applies is set per scheme, because a scheme whose every operation is a network round trip benefits from overlapping even two URIs.
