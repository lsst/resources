``HttpResourcePath`` now persists its cached ``requests.Session`` across context manager invocations so that underlying TCP/TLS connections remain open in the session pool instead of being closed at the end of each ``with`` block.
Streaming responses in ``HttpResourcePath.read()`` and ``_as_local()`` are now wrapped in context managers to promptly return connections to the pool, and ``HttpReadResourceHandle`` caches redirected back-end storage URLs across range reads for non-dCache servers with ``If-Match`` validation and automatic front-end fallback.
``HttpResourcePath`` connection pools now share a pre-configured ``ssl.SSLContext`` via a custom ``HTTPAdapter``, eliminating repeated CA bundle and client certificate file reads when opening connections to redirected storage hosts.
``HttpResourcePath`` now configures separate front-end and back-end connection pools via ``$LSST_HTTP_FRONTEND_PERSISTENT_CONNECTIONS`` and ``$LSST_HTTP_BACKEND_PERSISTENT_CONNECTIONS`` (replacing ``$LSST_HTTP_PERSISTENT_CONNECTIONS``), defaulting to non-persistent back-end connections (``Connection: close``) while keeping front-end redirector connections persistent.
